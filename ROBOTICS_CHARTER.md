# Robotics Research Charter

Status: experimental sibling surface to the existing optical work.

TranchNOSE tests whether physically instantiated relations can carry causally relevant machine state that is not reducible to one authoritative electronic copy.

Optics was the first carrier. Robotics is a second, independent crucible.

## Scope

The robotics track studies embodied state, morphology, contact, topology, environment coupling, challenge-response identity, and bounded adaptive change.

It does **not** assume:

- that a robot is conscious or a person;
- that embodiment proves relational memory;
- that simulation success is physical proof;
- that a controller is irrelevant;
- that provenance or history is automatically causally active;
- that a machine able to perform an action is authorized to perform it.

## Shared distinctions

The robotics experiments preserve these separations:

```text
controller state != body state
body state       != body topology
capability       != authority
observation      != intervention
prediction       != causal sufficiency
state similarity != history identity
name             != particular
receipt          != source authority
```

These are engineering constraints, not theological claims.

## Candidate machine model

A robotics experiment may describe a machine as:

```text
M(t) = {
  X(t),        controller/electronic state
  B(t),        embodied physical state
  G_body(t),   mechanical or morphological relations
  G_local(t),  administrative/coordination state
  E(t),        modeled environment state
  H(t)         attributable crossing history
}
```

The initial hypothesis is deliberately narrow:

```text
State(M) != X
```

A controller snapshot may be insufficient to predict or reconstruct behavior if causally relevant state is carried by morphology, contact, topology, environment coupling, or their relation.

## Experimental sequence

### R001 — Body State

Hold controller and stimulus constant. Change only declared morphology/body parameters. Test whether the trajectory follows the body condition.

This is a software protocol crucible before hardware.

### R002 — Address / Answer

Apply a pre-registered challenge set and compare characteristic response trajectories. Test whether state resemblance and dynamical response identity can diverge.

### R003 — Morphology / State Swaps

Construct counterfactual combinations of controller, body state, body topology, environment, and history. Measure which inherited component controls future behavior.

### R004 — Bounded Relational Learning

Only after the earlier experiments are coherent: allow the machine to **propose** topology changes while preserving:

```text
observe != propose != authorize != mutate
```

An adaptive proposal is not permission to alter physical configuration.

## Relation to Experiment 001A

Experiment 001A remains untouched and authoritative for its own optical field-object question.

Robotics does not reinterpret a successful optical run, and an optical result does not establish a robotics result.

The value of the second carrier is independent pressure:

- if a distinction survives only in one model, it may be carrier-local;
- if independently designed optical and embodied experiments require the same distinction, that is evidence of portability;
- neither case promotes metaphor into physical law.

## Cross-domain inspiration

The robotics track may preserve research inspirations from embodiment, cybernetics, dynamical systems, and historical/theological analogy, but executable claims must be stated in operational engineering terms.

The current Genesis/robotics research contributed several useful anti-collapse constraints:

```text
image != source
capability != authority
command != fence
crossing -> history
continuity != identical state
appearance != characteristic response
```

Those phrases are research provenance. Their executable meaning must be defined by tests and receipts in the owning experiment.
